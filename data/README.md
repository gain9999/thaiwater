# data/ — cached payloads and derived tables

Everything here is generated by the scripts in `tools/`; nothing is hand-edited. Raw API responses are
kept verbatim so the derived tables can be rebuilt without re-fetching.

| file | what it is | produced by |
|---|---|---|
| `waterlevel_load.json` | raw `public/waterlevel_load` (806 water-level gauges, nationwide, one snapshot) | `tools/fetch_nodes.py` |
| `watergate_load.json` | raw `public/watergate_load?basin_code=6..26` — gates, regulators, dams (one payload per basin) | `tools/fetch_nodes.py` |
| `station_nodes.csv` | merged node inventory, one row per station code | `tools/fetch_nodes.py` |
| `station_nodes.json` | same inventory with the records kept | `tools/fetch_nodes.py` |
| `node_summary.json` | counts (totals, wl/gate/chart coverage, per-family) | `tools/fetch_nodes.py` |
| `raw/cp.svg` | `waterchart.thaiwater.net` Chao Phraya schematic (the "brief chart") | downloaded |
| `raw/hii_chaophraya.html` | RID/HII 2013 full chart page with its 297 node divs (the "full chart") | downloaded |
| `raw/svg_paths.json`, `raw/svg_leaders.json` | river polylines and station leader lines extracted from the brief chart | `tools/svgnet.py` |
| `raw/travel_labels.json` | the 11 water-travel-time labels found in the brief chart, with SVG coordinates | `tools/travel_time.py` |
| `series_raw.json` | hourly water-level series cache (per station, ISO timestamps) | `tools/event_lag.py` |
| `event_lag_<YYYYMMDD>.csv` | one row per matched flood event: station pair, onset, lag in hours | `tools/event_lag.py` |
| `event_lag_<YYYYMMDD>.json` | same matches + per-pair median/min/max lag and the parameters used | `tools/event_lag.py` |

Refresh:

```
python3 tools/fetch_nodes.py          # node inventory (21 API calls, ~1 min)
python3 tools/svgnet.py               # chart geometry -> raw/svg_*.json
python3 tools/travel_time.py          # travel-time labels + coverage check
python3 tools/event_lag.py --days 45 --pause 25 --tries 4    # measured lags (slow: paces itself)
```

Notes

- `api-v3.thaiwater.net` throttles hard: a burst of ~20 requests returns `500: Internal Database Error …
  pq: out of shared memory`. Batch work should pace itself (the scripts do) and cache; re-runs reuse
  `series_raw.json` and skip stations already fetched.
- `station_nodes.csv` covers ~2270 codes: 806 with live water level, ~1576 gate/regulator/dam records,
  and 129 codes that exist only on the charts (no live telemetry on either public endpoint).
- The two chart pages are not equivalent: the 2013 full chart draws all 297 codes including every
  dam/regulator, while the modern brief chart draws 127 and relies on `watergate_load` for gates.
- Figures derived from these files are workload snapshots, not official published statistics.
